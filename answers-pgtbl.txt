The page table output from pgtbltest shows how the virtual addresses (VAs) of a user process are mapped to physical addresses (PAs), along with their permission bits.
The first few entries (VAs 0x0–0x4000) represent the process’s code and data segments. Each entry shows a valid mapping to a physical page (e.g., va 0x0 to pa 0x87F22000) with permissions 0x5B, which means the page is valid, readable, writable, executable, and accessible from user mode. These pages contain the user program’s text, data, and possibly part of its heap.
Addresses 0x5000–0x9000 are unmapped (PTE = 0), meaning there are no valid mappings for those virtual pages.
At the top of the user address space, the last two entries correspond to special kernel-managed pages used by every process.
va 0x3FFFFFE000 maps to pa 0x87F42000 with permissions 0xC7 (valid, readable, writable, executable, user accessible). This is the trapframe page, which stores the user’s saved registers during system calls and traps.
va 0x3FFFFFF000 maps to pa 0x80006000 with permissions 0x4B (valid, readable, executable, user accessible). This is the trampoline page, containing shared code that transfers control between user and kernel mode.
Overall, the output shows that the process’s code, data, and stack occupy the low addresses, while the trapframe and trampoline occupy the top addresses of the user virtual space.
