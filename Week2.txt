1. What Was Achieved in Week 2

Week 2 focused on implementing the actual Multi-Level Feedback Queue (MLFQ) scheduling logic inside xv6. All core scheduler features are now working:
    •    ✔ Priority-based scheduling across 4 queues (Q0–Q3)
    •    ✔ Time-slice enforcement using timer interrupts
    •    ✔ Automatic demotion for CPU-heavy processes
    •    ✔ Round-robin within each queue
    •    ✔ I/O-bound tasks maintain high priority
    •    ✔ Multiple test programs created and validated

The scheduler now behaves like a proper MLFQ system where CPU-bound and I/O-bound processes get treated differently.


2. Core Implementation

2.1 Modified scheduler() (kernel/proc.c)
    •    Scheduler now checks queues in order: Q0 → Q1 → Q2 → Q3
    •    It runs the first RUNNABLE process it finds in the highest non-empty queue
    •    Round-robin is maintained inside each queue
    •    After each run, the scheduler restarts scanning from Q0

This ensures responsiveness for interactive/I/O-heavy processes.


2.2 Time-slice Tracking (usertrap() in trap.c)
    •    Every timer interrupt increases the running process’s time_slices
    •    The scheduler tracks CPU time per queue

Timer interrupts (device 2) trigger yield checks, ensuring accurate quantum usage.


2.3 Demotion Logic

A process is moved to the next lower queue only when it uses its entire time quantum:
    •    Q0: 2 ticks → demote to Q1
    •    Q1: 4 ticks → demote to Q2
    •    Q2: 8 ticks → demote to Q3
    •    Q3: stays at Q3

After demotion:
    •    priority++
    •    time_slices = 0

Voluntary yield = process stays in current queue.
